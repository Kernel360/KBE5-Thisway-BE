# ADR-008: 완료 운행 시간 기반 가동률 V2

2026-09-06, 채택. 사용자가 새 지표 방향의 판단·구현을 위임했다. 현대오토에버 시니어
개발자/면접관의 관점은 멘토링 역할이며 실제 소속을 의미하지 않는다. 원 RFP 미보유 상태에서
원 요구사항을 복원한 것이 아니라 현재 포트폴리오의 지표 정의를 명시적으로 변경한다.

## 의미와 대안

기존 GPS 행 수/(3600×차량 수)는 GPS 수집 주기를 1초라고 가정하고 누락/전송 주기에 영향을
받았다. GPS 미수신과 차량 비가동은 같은 사실이 아니다.

| 선택 | 장점 | 위험 | 결정 |
| --- | --- | --- | --- |
| GPS 개수 유지/주기 곱하기 | 기존 구조 간단 | 누락·주기 이력·중복과 실제 운행을 혼동 | 거절 |
| 완료 Trip ON~OFF 합집합 | 시간 정의/검증이 명확 | 미종료 제외, 늦은 OFF에 보정 필요 | 채택 |
| 속도 기반 실제 이동 시간 | 정차와 이동 구분 | GPS 간격 보간/품질/속도 기준 필요 | 별도 지표로 보류 |

## 공식

- 모집단: **계산 시점 해당 회사의 active Vehicle**. 일자별 fleet 수를 저장한다.
- 유효 운행: active(현 모델에서 완료 의미)이고 `endTime > startTime`인 Trip.
- 일자 구간은 한국 로컬 시각 `[00:00:00, 다음날 00:00:00)`.
- 유효 운행을 일자에 clip하고 **동일 차량별 중복·겹침·인접 구간을 union**한다.
- 시간별 가동률: `그 시간 내 union 가동 나노초 합 / (3600초 × 모집단 차량 수) × 100`.
- 일평균: 24개 시간별 가동률의 평균. 기간 평균은 **집계된 V2 일별 값의 단순 평균**.
  차량 수가 다른 날짜를 vehicle-time 가중 평균하는 정의는 아니다.
- 총 가동 시간: union의 나노초를 모두 합산한 후 분 단위 내림. 기간 합산은 일별 저장 분의 합.
  하루별 내림에 따른 초 미만/분 미만 차이는 남는다.
- 차량 0대는 0을 저장한다. 계산기에 모집단보다 많은 차량의 구간이 들어오면 실패시킨다.
- 시동 횟수: 당일 `vehicle_id + start_time` distinct. 직접 수신한 ON이 아니라 Trip에 기록된 시작 수다.
  OFF만으로 복원된 startTime도 포함하며 원본 ON 수신 수라고 주장하지 않는다.

예: 차량 2대, union 합계 300분 → 300/(2×1440)×100 = 10.4167%.
이는 **정차/공회전을 포함한 시동 가동 시간**이지 물리적 이동 시간이나 영업시간 대비 가동률이 아니다.

## GPS와 불완전 데이터

`gpsObservationCount`는 같은 모집단/날짜에서 DB에 저장된 GPS row 수다. packet 수,
수신율, 정상 GPS 비율, 고유 위치 수가 아니다. 신규 observation의 기존 멱등성 범위 밖인
legacy 중복이나 같은 시각의 다른 관측값도 row 수에 포함한다. 분모를 추측해 수신율을 만들지 않는다.

`unclosedTripCount`는 dayEnd보다 전에 시작했으나 계산 시점에도 endTime이 없는 행 수다.
기간 응답의 `unclosedTripDays`는 일별 값을 합한 **건·일**이며 고유 Trip 수가 아니다.
미종료 구간은 지금 시각까지 늘리지 않는다. 역전/영길이 구간도 가동 시간에 포함하지 않는다.
데이터가 전부 도착했다는 증거는 없으므로 0 가동률이 실제 비가동 확정이라는 보장은 없다.

## 버전·보정·기간

V5는 기존 statistics와 checkpoint를 formulaVersion=1로 보존한다. 새 계산만 V2로 기록하며
fleet 수/GPS 행 수/미종료 수/계산 시각을 함께 저장한다. 옛 숫자를 V2라고 relabel하지 않는다.
조회는 V2만 합산하고 quality에 requestedDays/coveredDays/excludedLegacyDays를 반환한다.
미집계/구버전 일자는 0일로 평균에 섞지 않는다. coveredDays=0의 숫자 0은 호환용 빈 결과이며
FE는 값 대신 `-`와 재집계 안내를 표시한다. 위치 통계는 별도의 현재 원천 조회임을 화면에 명시한다.

저장은 종료된 한국 날짜만 허용한다(오늘/미래 거부). 기간 조회는 역순을 거부하고 최대 366일이다.
회사별 lock/unique는 유지한다. checkpoint와 해당 결과가 모두 현재 버전인 경우에만 건너뛴다.
완료된 JobInstance를 timestamp로 우회하지 않는다. 보정은 기존 ADMIN 저장 경로로 해당 날짜를
다시 계산하여 같은 row를 갱신한다. 자동 backfill/late-event 탐지/수정 이력 revision은 아직 없다.

## 제한

과거 회사 소속/차량 active 이력 snapshot이 없어 과거 fleet을 정확하게 재현하지 못한다.
완료 Trip 원천의 신뢰성은 별도 상태 머신 문제이며, 구간 union은 raw Trip 중복을 삭제하지 않는다.
회사별 모든 겹치는 운행을 메모리에 가져온다. 대규모 운행 수의 query/p95/메모리는 미측정이다.
실제 운영 DB migration이나 통계 보정은 이번에 실행하지 않는다.
